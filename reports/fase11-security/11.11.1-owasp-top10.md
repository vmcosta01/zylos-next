# 11.11.1 — OWASP Top 10 (revisão estática do gateway)

**Escopo:** `apps/zylos-gateway/src` (~6.1k linhas) + crates que montam rotas no gateway (`crates/zylos-live-comm/src/routes.rs`).
**Método:** revisão estática de código (sem pentest dinâmico contra instância rodando). Branch `feat/f11-security`.
**Pentest dinâmico:** ver [11.11.1-pentest-dinamico.md](./11.11.1-pentest-dinamico.md) para testes contra instância rodando (2026-11-18).

## Modelo de exposição
- Bind padrão `127.0.0.1:3000` (`apps/zylos-gateway/src/config.rs:76-78`), sobrescrito por `ZYLOS_LISTEN` (`config.rs:164`).
- Middleware mais externo `local_guard::so_desta_maquina` (`apps/zylos-gateway/src/lib.rs:233`, `apps/zylos-gateway/src/local_guard.rs:100-122`): recusa `Origin` não-local e `Host` não-local (anti-CSRF e anti-DNS-rebinding de navegador).
- **Consequência:** o modelo de segurança do gateway é "só esta máquina". A maioria das rotas **não tem autenticação**; a proteção é a fronteira de rede + checagem de Origin/Host.

## A02 — Cryptographic Failures
- JWT: segredo fallback `"dev-secret-change-me-in-production"` removido (era `crates/zylos-auth/src/tokens.rs:36` antes de 25fe4a5) — **Crítico, corrigido** (ver 11.11.2).
- `ZYLOS_SOAR_AUDIT_KEY` tem default fixo `"zylos-gateway-soar-key"` (`apps/zylos-gateway/src/config.rs:88-90`) usado para assinar a trilha de auditoria SOAR (`main.rs:118`) — **Médio, aberto**: assinaturas forjáveis se o default não for trocado.
- Cache: `Cache-Control: no-store` em todas as respostas (`apps/zylos-gateway/src/security_headers.rs:42`).

## A03 — Injection
- SQL: `crates/zylos-channels/src/store.rs` usa queries parametrizadas (`?` bind, ex. `:145`, `:219`). Nenhum `format!` montando SQL encontrado no gateway (grep `format!("SELECT|INSERT|DELETE`).
- Comando: único `Command::new` alcançável é `crates/zylos-soar/src/yaml_runbook.rs:23-25` (shell com string de runbook). Entrada vem de arquivos YAML, não da requisição HTTP → risco depende da integridade do diretório de runbooks (Médio).
- Path traversal: gateway não serve arquivos a partir de entrada do usuário (`std::fs` só em `config.rs:151` com caminho de config). Capability tokens negam `..` (`crates/zylos-agent-shield/src/capability_token.rs:112`). OK.

## A04 — Insecure Design
- Ausência de rate limiting em todo o gateway (nenhum `GovernorLayer`/limiter no router; `hermes_employee_api.rs:97` só reporta estatística). `/auth/login` permite brute-force do bootstrap token (mitigado por ≥32B aleatórios). **Médio, aberto.**
- Sem `DefaultBodyLimit` explícito: axum 0.7 aplica 2 MB padrão ao extrator `Json` — aceitável. WebSocket sem limite de sessões: `webrtc_relay.rs:82-92` cria canal por `session_id` arbitrário (DoS de memória) — **Baixo/Médio, aberto**.

## A05 — Security Misconfiguration
- Headers de segurança adicionados (35d4770): `apps/zylos-gateway/src/security_headers.rs:19-44` — ver 11.11.7.
- CORS restrito a origens locais (`lib.rs:224-231`, `local_guard.rs:79`), mas `allow_methods(Any)`/`allow_headers(Any)` — Baixo.
- **Inconsistência de deploy:** `Dockerfile:64` e `docker-compose.yml:17` usam `host = "0.0.0.0"`/`ZYLOS_HOST`, chaves que o gateway **não lê** (só `ZYLOS_LISTEN`); dentro do container o gateway ficaria em 127.0.0.1 (healthcheck `Dockerfile:79` funciona, port-forward não). Se alguém "corrigir" para `ZYLOS_LISTEN=0.0.0.0`, A01-2 vira crítico. `local_guard` ainda bloqueia `Host` não-local, o que mitiga navegador mas não clientes não-browser que forjam `Host: localhost`. **Alto (risco de configuração), aberto.**
